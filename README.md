# Сайт ЦПРПП м. Лубни

Сайт Комунальної установи «Центр професійного розвитку педагогічних працівників
Лубенської міської ради» Лубенського району Полтавської області.

Це перенесений на Next.js сайт, який раніше працював на TiddlyWiki за адресою
`lubny-cprpp.ho.ua`. Увесь вміст лежить у репозиторії у вигляді Markdown і YAML,
редагується через веб-панель і публікується автоматично.

## Як це влаштовано

| Що | Чим |
| --- | --- |
| Сайт | Next.js 16 (App Router), Tailwind CSS 4 |
| Вміст | Markdown + YAML у теці `content/` |
| Редагування | Decap CMS на `/admin`, вхід через Netlify Identity |
| Публікація | Netlify, автоматично після кожної зміни в гілці `main` |

Сайт повністю статичний: усі сторінки збираються заздалегідь і віддаються з CDN,
жодних серверних функцій у рантаймі немає.

## Редагування вмісту

Редакторам не потрібно нічого встановлювати — усе робиться через браузер:

1. Відкрити `https://<адреса-сайту>/admin`
2. Увійти через Netlify Identity
3. Внести зміни й натиснути «Зберегти»

Матеріал спершу стає **чернеткою** — на сайті його ще не видно.

Щоб опублікувати:

1. У вкладці **«Редакційний документообіг»** (угорі поруч зі «Змістом») знайти
   картку матеріалу. Вона стоїть у колонці **«Чернетки»**.
2. Перетягнути її до колонки **«Схвалено»** (проміжна — «На розгляді»).
3. Натиснути **«Опублікувати зміни»**.

Опубліковані зміни зберігаються як коміт у гілку `main`, після чого Netlify
перезбирає сайт; оновлення з'являється за кілька хвилин.

> Кнопка «Зберегти» лише зберігає чернетку. Доки картка не пройде до
> «Схвалено» й не буде натиснуто «Опублікувати зміни», на сайті нічого
> не з'явиться.

### Сторінки складаються з блоків

Постійні сторінки редагуються не суцільним текстом, а блоками — їх видно
списком і можна переставляти перетягуванням:

Назви блоків тут — точно ті, що видно в адмінці:

| Блок | Для чого |
| --- | --- |
| Текст | Звичайні абзаци |
| Оголошення | Виділена рамка вгорі сторінки |
| Розгортуваний розділ з текстом | Суцільний текст, який розкривається клацанням |
| Список новин за темою (оновлюється сам) | Сюди самі потрапляють публікації з відповідною темою |
| Список новин (обираються вручну) | Публікації обираються зі списку по одній |
| Перелік документів і посилань | Накази, бланки, посилання; підтримує вкладені додатки |
| Таблиця (керівники, контакти) | Керівний склад, контакти закладів |
| Фотогалерея | Фото з підписами |
| Логотипи партнерів | Плитка логотипів («Ми співпрацюємо») |

Адреса сторінки чи новини складається автоматично з назви — вигадувати її
латиницею не треба.

Покрокова інструкція для редактора — в окремому файлі:
[ІНСТРУКЦІЯ.md](ІНСТРУКЦІЯ.md).

### Теми новин

У новини є поле «Теми». Якщо поставити, скажімо, «Шкільна бібліотека», публікація
**сама** з'явиться в списку «Події» на відповідній сторінці — додавати посилання
вручну не потрібно.

Раніше ці списки вели руками, і вони систематично відставали: у «Дошкіллі»
бракувало 12 профільних новин, на сторінці сертифікації — навіть найсвіжішої.

Теми збігаються з адресами сторінок спільнот. Щоб з'явилася нова тема, на
потрібній сторінці має бути блок «Список новин за темою», а саму тему треба
додати до переліку в `public/admin/config.yml` — у двох місцях, для новин
і для блока.

### Пошук

Пошук по сайту (`/poshuk`) працює в браузері за покажчиком, який збирається
під час збірки (`lib/search-index.ts`). Окремо його оновлювати не треба.

### Де що лежить

```
content/
  news/       новини (по файлу на публікацію, ім'я = дата + назва латиницею)
  pages/      статичні сторінки (Атестація, Сертифікація тощо)
  team/       працівники Центру
  settings/
    site.yml        контакти, графік роботи, партнери
    navigation.yml  меню сайту
public/images/  фотографії та інші файли
```

## Локальна розробка

Потрібен Node.js 22+ і pnpm (версія закріплена в `packageManager`, тож
`corepack` підтягне саме її).

```bash
pnpm install
pnpm dev        # http://localhost:3000
```

Інші команди:

```bash
pnpm build        # продакшн-збірка
pnpm start        # запустити зібраний сайт
pnpm lint         # ESLint
npx tsc --noEmit  # перевірка типів
```

Щоб працювати з CMS локально, розкоментуйте `local_backend: true`
у `public/admin/config.yml` і запустіть `npx decap-server` окремим процесом.

## Структура коду

```
app/                маршрути (App Router)
  page.tsx            головна
  [slug]/             статичні сторінки з content/pages
  novyny/             стрічка новин, архів за роками, пагінація
  komanda/            команда Центру
  sitemap.ts          карта сайту
  robots.ts
components/         компоненти інтерфейсу
lib/
  content.ts          читання Markdown і YAML із content/
  markdown.ts         конвертація Markdown у HTML (із санітизацією)
  news-archive.ts     логіка стрічки та пагінації
  site-url.ts         базова адреса сайту
  legacy-redirects.json  карта переходів зі старого сайту (генерується)
scripts/            допоміжні скрипти (див. нижче)
```

### Адреси стрічки новин

```
/novyny                        усі новини, перша сторінка
/novyny/storinka/3             усі новини, третя сторінка
/novyny/rik/2024               публікації за 2024 рік
/novyny/rik/2024/storinka/2    другий екран 2024 року
```

## Скрипти обслуговування

```bash
node scripts/generate-redirects.mjs    # оновити карту переходів зі старого сайту
node scripts/fix-descriptions.mjs      # перевірити описи новин (--apply щоб записати)
node scripts/fix-tiddly-leftovers.mjs  # прибрати залишки розмітки TiddlyWiki
node scripts/compress-images.mjs       # стиснути зображення
```

`scripts/migrate.mjs` — одноразова міграція зі старого TiddlyWiki-сайту.
Вона більше не запускається: старий сайт недоступний. Скрипт лишається
як документація того, звідки взявся вміст; результат — у `migration-report.json`.

## Оновлення адмінки

Decap CMS і віджет Netlify Identity лежать локально в `public/admin/vendor/`,
а не тягнуться з CDN — щоб оновлення стороннього пакета не могло само собою
отримати доступ до репозиторію сайту.

Щоб оновити версію:

```bash
npm pack decap-cms@<версія>
tar xzf decap-cms-<версія>.tgz
cp package/dist/decap-cms.js public/admin/vendor/decap-cms-<версія>.js
```

Далі оновити шлях у `<script>` в `public/admin/index.html` і видалити старий
файл. Так само для `netlify-identity-widget`.

| Змінна | Навіщо |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Базова адреса сайту. Якщо не задано, береться Netlify-змінна `URL`, тож після перенесення домену правити код не треба. |

## Що варто знати

- **Переходи зі старого сайту.** `lib/legacy-redirects.json` містить 305 правил
  із адрес виду `/notes/<назва>.html`. Вони спрацюють лише тоді, коли домен
  старого сайту вказуватиме на цей Netlify-сайт.
- **Теги новин** у файлах вмісту — це автоматичні мітки з TiddlyWiki
  (`2024`, `Березень2024`). Вони дублюють дату публікації й ніде не показуються.
- **Двокрапка в тексті `config.yml` ламає всю адмінку.** Рядок виду
  `hint: Потрібна, навіть якщо є логотип: її читають...` робить YAML
  невалідним, і Decap показує «Error loading the CMS configuration» замість
  інтерфейсу — редагувати сайт стає неможливо. Значення з `: ` беріть у лапки.
  Пастка в тому, що `js-yaml` таке проглядає, а строгий парсер Decap — ні,
  тож перевірка скриптом дає фальшивий спокій. Після кожної правки конфігу
  відкривайте `/admin` у браузері.
- **Зображення не оптимізуються** (`images.unoptimized`), бо збірка статична.
  Що завантажили, те й віддається; періодично проганяйте
  `node scripts/compress-images.mjs`.
- **Вміст санітизується.** `lib/markdown.ts` пропускає HTML із Markdown через
  allowlist. Якщо колись знадобиться вбудовувати відео, `<iframe>` треба буде
  додати туди явно, разом зі списком дозволених доменів.
